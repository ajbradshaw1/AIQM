\manualsection{1}{Understand the live and offline paths}

\inbrief{The live GUI creates immutable session evidence. The offline labeler reviews manual, automatic-change, and posthoc point events. Equalizer remains separate from human interpretation and model output.}

The live GUI performs acquisition and display. The offline labeler works only on completed archived sessions. Never interpret an offline result as a real-time control instruction.

\begin{corebox}{The boundary between the applications}

\begin{warnbox}{Keep the concepts separate}
Human surface-reconstruction interpretation, Equalizer visual fit, image acquisition quality, model output, and FeSe film quality are different concepts. Image acquisition quality means only whether a captured frame can be analyzed; it never means poor surface or film quality. The current classifier concerns the bare STO surface before growth.
\end{warnbox}

\subsection{Operating principle}
\begin{itemize}
  \item The selected O-MBE or Ch-MBE GUI reads live instrument sources and writes chamber-identified session records under the operator's control.
  \item Post-processing combines an archived session with one or more already-generated prediction tables.
  \item Reviews are stored as frame-bound point events with immutable source evidence and append-only revisions.
  \item Equalizer is an auxiliary four-basis visual fit; it never fills or overwrites a human reconstruction field.
  \item Model outputs remain visible, so these annotations are assisted review, not blind-gold labels.
\end{itemize}

\manualsection{3}{Understand Configuration modes and chamber defaults}

\inbrief{Both chambers start with \texttt{vimba}, \texttt{modbus}, \texttt{ads}, and \texttt{elog}: direct reads for RHEED, temperature, MISTRAL, and EvapControl. \texttt{dummy} modes generate test data and must not be mistaken for instruments.}
\label{sec:chamber-defaults}

The Configuration panel chooses one reader for each data source. A mode selects \emph{how the GUI reads}; it does not change an instrument setpoint. The four selectors are independent, and their selected values are frozen when the session is armed.

\subsection{Vimba exposure and ARM fail-closed behavior}
The \textbf{Direct exposure} control applies only to \texttt{vimba}. The current O-MBE profile requests 500~ms and the current Ch-MBE profile requests 300~ms during ARM. They are deliberately different software requests, not transferable chamber setpoints or operating authorization. The confirmed camera readback, not the displayed request alone, is the evidence of what was applied. The control is locked while armed or running.

\begin{itemize}[itemsep=1.2pt,topsep=1pt]
  \item A nonzero request is a volatile camera write. It requires Full camera access and \texttt{ExposureAuto=Off}. Close kSA or Vimba X Viewer when either application prevents Full access.
  \item Zero displays \textbf{Keep current}. It performs no exposure write, although the driver still reads and records the current exposure when available.
  \item The UI and driver reject non-finite, out-of-range, or unsafe exposure and trigger combinations. The ceiling keeps at least 10 percent of the trigger period for acquisition overhead: 900~ms at the default 1~Hz rate.
  \item After writing, the driver reads the feature back. ARM succeeds only when the requested value can be proven applied. On a post-write failure, the driver attempts a verified restoration of the original exposure; an unverified restoration remains an explicit stop condition.
  \item The application never calls \texttt{UserSetSave}. The change is volatile, and a camera power cycle restores the stored camera user set.
\end{itemize}

Session metadata stores \texttt{camera\_exposure\_requested\_ms} separately from \texttt{camera\_exposure\_readback\_ms}. \textbf{Keep current} therefore has a null request and may still have a numeric readback. A request without a matching confirmed readback is not proof that the camera accepted it.

\subsection{Camera ownership, freshness, and start gate}
ARM is one cancellable startup transaction. A failed or abandoned setup releases the worker and camera ownership before the GUI returns to idle; never start a second GUI to work around an ARM failure. The direct Vimba path does not re-serve its cached last frame as a new acquisition. Capture sequence and arrival time must advance, and START remains disabled until the current ARM cycle delivers a qualifying live frame. If delivery stalls, DISARM and investigate camera ownership, triggering, sequence, age, and the recorded error rather than treating the last displayed image as current data.

Windows Graphics Capture can read a detached kSA \textit{Live Video} window while another window covers it, but it fails closed if the source window is minimized, closed, or stops delivering new frames. \texttt{screengrab\_mss} remains a monitor-pixel diagnostic fallback that can be contaminated by overlap, position, scaling, and display changes.

% Page 6 - inputs
\manualsection{5}{Prepare inputs and verify provenance}

\inbrief{Preserve the ZIP and exact saved frames. Manual marks and automatic image-change points become editable Drafts; adjustment, image-unusable, and instrument records remain read-only references.}

\subsection{Session archive}
The ZIP archive must contain exactly one member ending in \texttt{session\_metadata.json}, exactly one member ending in \texttt{heartbeat\_log.csv}, and every sibling \texttt{frames/} image referenced by the heartbeat rows. Saved-frame elapsed time, heartbeat index, capture sequence, and timezone-aware capture UTC must each increase strictly; gaps are allowed. Do not extract and rename frames manually.

Read \texttt{chamber\_id} from the session metadata and confirm that it names the intended O-MBE or Ch-MBE source. For Modbus, preserve COM, baud, RTS, device ID, and backend. For ADS, preserve endpoint, ports, and cell count. For Elog, preserve the configured directory and resolved source file. Compare provenance only with the corresponding startup-default record in Chapter~\ref{sec:chamber-defaults}; never edit an archive to make it resemble the other chamber.

\begin{lstlisting}
growth_session.zip
  session_metadata.json
  heartbeat_log.csv
  frames/
    heartbeat_000001_....bmp
    heartbeat_000002_....bmp
\end{lstlisting}

\subsection{Prediction tables and model specifications are positional pairs}
\rowcolors{2}{ManualPale}{white}
\begin{tabularx}{\linewidth}{L{31mm}L{82mm}Y}
\toprule
\textbf{File} & \textbf{Required content} & \textbf{Check} \\
\midrule
Prediction CSV & frame index, heartbeat index, elapsed time, capture UTC, capture sequence, frame name, frame SHA-256, and score columns & Rows match the saved-frame order exactly \\
Model-spec JSON & schema version 1, non-empty key and title, at least two unique classes, and equally sized unique probability columns & Class order matches the score columns; status and provenance are optional \\
Session ZIP & metadata, heartbeat log, and frames & Every referenced frame exists in the archive \\
\bottomrule
\end{tabularx}

Prediction \texttt{frame\_index} may begin at 0 or 1, but it must then remain contiguous. Heartbeat indices, capture sequences, and elapsed times may contain gaps. The tool follows actual saved frames and recorded times; it never assumes exact 1 Hz sampling.

\begin{dangerbox}{Fail closed}
Any mismatch in row count, order, time, sequence, filename, or SHA-256 stops the build. Do not edit the inputs to bypass an error.
\end{dangerbox}

\subsection{Event and context sources}
\begin{itemize}
  \item \texttt{manual}: one-click \textbf{MARK EVENT} evidence created during acquisition; an empty comment remains Unfinished.
  \item \texttt{auto\_capture}: a point produced by the RHEED image-change detector. It marks a visual change, not its physical cause.
  \item \texttt{posthoc}: a point added later at an actual saved frame.
  \item RHEED direction, beam-current, and beam-energy adjustments are read-only reference points.
  \item An image-unusable record means only that acquisition or capture made the image unsuitable for analysis. It is not a surface-quality or film-quality judgment.
  \item Temperature, voltage, current, pressure, and data age come from original logs and remain read-only context, not editable label fields.
\end{itemize}

\manualsection{6}{Build and open a report safely}

\inbrief{Build only into a new or empty directory outside Git. Preserve the complete report directory and the original prediction/model-spec inputs separately.}

Older \texttt{events\_labels.csv} rows may seed automatic-event review. A legacy \texttt{live\_labels.csv} row links only when capture sequence and frame SHA-256 identify exactly one event. Legacy temporal segments remain readable but are not converted automatically because a segment has no unique scientific point.

\subsection{Recommended local layout}
\begin{lstlisting}
<local-data-root>\2026-08-11_anneal\
  source\growth_session.zip
  predictions\model_A.csv
  specs\model_A.json
  output\
  exports\
\end{lstlisting}

\step{1}{Choose the preserved archive copy in Session ZIP.}
\step{2}{Add one Prediction CSV and Model-spec JSON row for every model to display. Pairing is positional, so preserve row order.}
\step{3}{Choose a new or empty directory outside the repository. The desktop labeler will not overwrite a non-empty directory.}
\step{4}{Enter a report title. Review quality changes only the lossy review images; it never changes archived pixels or model predictions. The default value of 78 is suitable for routine use.}
\step{5}{Click \textbf{Build report and open}. Wait for success and for \texttt{interactive\_report.html} to open automatically.}

\subsection{PowerShell fallback}
\begin{lstlisting}
Set-Location '<GUI repository>'
conda activate ai4mbe-gui
python -m tools.rheed_postprocessing_labeling build `
  --session '<local-data-root>\growth_session.zip' `
  --predictions '<local-data-root>\predictions.csv' `
  --model-spec '<local-data-root>\model_spec.json' `
  --output-dir '<local-data-root>\point-event-review'
\end{lstlisting}

\subsection{Copy the entire report directory}
The report consists of \texttt{interactive\_report.html}, \texttt{images/}, \texttt{vendor/}, \texttt{run\_manifest.json}, and its adjacent \texttt{annotations/} sidecar. Copy the entire directory during handoff. Preserve the original prediction CSV and model-spec JSON separately outside the report directory. Review WebP files are display copies only; Equalizer reads the original BMP or PNG bytes from the read-only ZIP.

\begin{warnbox}{Advanced CLI overwrite boundary}
The desktop application always refuses a non-empty output directory. CLI \texttt{-{}-overwrite} may replace only a recognized, unmodified tool output. It validates the new inputs and stages a complete replacement first. If the old report changes during the build, replacement stops and the original content is restored. Filesystem roots, repository paths, the current directory, and directories containing inputs are always rejected.
\end{warnbox}

% Chapter 7 - point events
\manualsection{7}{Review and complete point events}

\inbrief{Select an Unfinished point, snap its review anchor to the best saved frame, add comment and reviewer, run Equalizer, and explicitly click Complete. There are no Mark In or Mark Out interval controls.}

The \texttt{rheed-point-events-v1} schema has three editable sources: \texttt{manual}, \texttt{auto\_capture}, and \texttt{posthoc}. Multiple events may share one timestamp or frame while keeping different IDs. Current events use UUIDs; legacy IDs deterministically include session, source file, source index, time, and capture sequence.

\subsection{Immutable original point and editable review point}
The original point retains event ID, source, time, source frame when available, capture sequence, image SHA-256, original note, and source-row SHA-256. It never moves. The review point can move only by snapping to an actual saved frame. Moving it clears the old Equalizer measurement because that result belonged to a different image.

\step{1}{Select an event in \textbf{Unfinished}, or choose \textbf{Add posthoc event at playhead} on an actual saved frame.}
\step{2}{Compare the immutable original marker with the movable review marker. Move only when another saved frame is a better review anchor.}
\step{3}{Enter a meaningful comment and reviewer. Confidence and human reconstruction before/after fields are optional.}
\step{4}{Click \textbf{Run Equalizer}; align and confirm handedness when no compatible accepted calibration exists.}
\step{5}{Adjust and save Equalizer, save the Draft, and click \textbf{Complete} explicitly.}

\manualscreenshot[width=0.88\linewidth,height=70mm,keepaspectratio]{assets/screenshots/rheed_timeline_editor.png}
\screenshotcaption{The actual point-event editor using generated demo inputs. Point markers and the Unfinished queue replace the former interval-label controls.}

Complete requires a nonempty comment, reviewer, saved review frame, and valid Equalizer result for that exact frame. Editing a completed event's comment, review point, or Equalizer returns it to Draft. Use \textbf{Reopen} for intentional further review.

\begin{warnbox}{Deletion and dismissal}
A source event from \texttt{manual} or \texttt{auto\_capture} cannot be deleted. It may be dismissed only with a reason, preserving the evidence. A \texttt{posthoc} event can be deleted and restored through audited revisions.
\end{warnbox}

% Chapter 8 - Equalizer and display
\manualsection{8}{Interpret Equalizer, logs, and display controls}

\inbrief{Equalizer is a separate visual fit, sensor values are read-only context, and brightness, contrast, zoom, and enlargement never modify archived pixels or model outputs.}

Equalizer runs only for the selected event. It records calibration and basis-bundle IDs, raw/final/normalized weights, fit residual, valid coverage, and the exact frame hash. The active bases are \texttt{1x1}, \texttt{Tw}, \texttt{c6x2}, and \texttt{RT13}. HTR has no canonical basis and must remain null.

\begin{dangerbox}{Equalizer is not a label or probability}
Equalizer weights are a visual linear fit. They are not model probabilities, area fractions, or a human reconstruction judgment. Equalizer never fills or overwrites a human reconstruction field, and model argmax never overwrites Equalizer or human review.
\end{dangerbox}

When no compatible calibration exists for the selected frame, view segment, geometry, and basis hash, complete the existing three-point alignment and handedness confirmation. Equalizer reads the original BMP or PNG from the ZIP, not a lossy WebP preview.

\manualscreenshot[width=0.76\linewidth,height=62mm,keepaspectratio]{assets/screenshots/rheed_timeline_zoom.png}
\screenshotcaption{The actual enlarged-frame dialog. Its timeline changes the selected saved frame while preserving zoom, pan, brightness, and contrast.}

The image, playhead, model guides, point markers, and enlarged timeline remain synchronized. Temperature, voltage, current, pressure, and data age are looked up from the original logs at event time and remain read-only. A common displayed time does not prove physically simultaneous sampling.

% Chapter 9 - persistence
\manualsection{9}{Preserve revisions, drafts, and exports}

\inbrief{Every edit is append-only. The source ZIP and acquisition CSVs remain unchanged, offline changes live in \texttt{annotations/}, and canonical JSON retains more provenance than CSV.}

Every revision records actor, UTC, action, complete before/after state, and base revision ID. Live sessions write \texttt{rheed\_event\_revisions.jsonl} plus a rebuildable current-state summary. Offline review writes an adjacent sidecar; it never changes the ZIP. A transaction marker permits exactly-once recovery after interruption.

Browser local storage is only a convenience Draft. Export JSON frequently. CSV is useful for tables and collaboration but does not replace nested event, Equalizer, and revision provenance in JSON.

\begin{lstlisting}
python -m tools.rheed_postprocessing_labeling validate `
  --report '<local-data-root>\point-event-review\interactive_report.html' `
  --annotations '<local-data-root>\point-event-review\annotations\point_events.json'
\end{lstlisting}

Validation binds the archive, ordered frame hashes, model context, event IDs, immutable source evidence, review anchors, revision chain, Complete gate, and Equalizer frame hash. Never bypass a mismatch. Old \texttt{rheed-temporal-segments-v1} files remain available to their original validator as read-only compatibility data; do not convert segment start, middle, or end into a point automatically.

\manualsection{10}{Data safety and scientific boundaries}

\inbrief{Keep real laboratory data and outputs out of Git. This workflow is model-assisted review of bare STO reconstruction, not blind-gold truth, acquisition-quality labeling, or FeSe film-quality evaluation.}

\toprule
\textbf{May be tracked} & \textbf{Keep out by default} \\
\midrule

\bottomrule

Model plots and Equalizer are visible during this workflow, so its reviews are model-assisted and not blind gold. Image acquisition quality means whether a captured frame can be analyzed. It is never evidence of poor surface or film quality. The current reconstruction target is bare STO before growth, not FeSe film quality.

Preserve the read-only source ZIP and SHA-256, report manifest, revision journal, canonical JSON, model specifications, and complete report directory during handoff.
